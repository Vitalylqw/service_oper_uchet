# Project Conventions For Codex

## Среда

- Ubuntu
- devcontainer
- локальная работа в VS Code

## Архитектура

- Используй DDD-подход со слоями `domain`, `application`, `infrastructure` внутри `src/`.
- Основной язык разработки: Python.
- Основная СУБД проекта: PostgreSQL.

## Правила импортов

- Между слоями внутри `src/` используй относительные импорты.
  Пример: `from ..database.models import ReadModelPosition`
- Внутри одного слоя используй абсолютные импорты относительно текущего пакета.
  Пример: `from .models import SyncConfiguration`
- Вне `src/` допускаются любые импорты, если это нужно для тестов и скриптов.

## Стандарты кода

- Соблюдай PEP 8.
- Максимальная длина строки: 100 символов.
- Используй docstring в Google-стиле на английском языке.
- Используй явные аннотации типов по PEP 484.
- Добавляй `from __future__ import annotations`, если это уместно для изменяемого модуля.
- Inline-комментарии оставляй только для нетривиальных участков.
- Используй подробное логирование там, где это помогает трассировать поведение системы.
- Не выдумывай версии библиотек: проверяй их в `pyproject.toml`.

## Проверки и инструменты

- Основной линтер: `ruff check .`
- Для типовой проверки ориентируйся на `docs/DEVELOPMENT_GUIDE.md`.
- Коммиты и docstring должны быть на английском языке.
- При описании git-коммитов используй Conventional Commits.

## Документация проекта

- `docs/` содержит проектную техническую документацию и сценарии разработки.
- `project_progress/` содержит динамику проекта и обзор текущего состояния.
