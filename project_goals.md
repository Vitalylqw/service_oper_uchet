# Цели проекта

## Основная цель

Приложение предназначено для синхронизации базы данных с данными, содержащимися в Excel-файле:

`data/real_data_for_testing/Data_source_excel.xlsx`

Состояние базы данных должно строго соответствовать данным, представленным в указанном Excel-файле, с учётом правил синхронизации, описанных ниже.

---

## Структура данных

В системе синхронизации используются следующие таблицы базы данных:

### Read-модель

- `read_deals` — таблица сделок  
- `read_positions` — таблица позиций внутри сделок  

Данные таблицы отражают актуальное состояние Excel-файла.

### Хранилище событий

- `event_store` — таблица для хранения всех выявленных изменений (событий)

---

## Логика синхронизации

Система должна автоматически выявлять следующие типы изменений в Excel-файле:

- `INSERT` — добавление записей  
- `UPDATE` — изменение записей  
- `DELETE` — удаление записей  

При обнаружении изменений система обязана:

1. Зафиксировать соответствующее событие в таблице `event_store`.
2. Обновить таблицы `read_deals` и `read_positions` в соответствии с текущим состоянием Excel-файла.

---



## Принцип атомарной обработки сделки

Единица обработки -- сделка целиком (deal + все позиции). Отдельные позиции не обрабатываются по одной.

### INSERT / UPDATE сделки

При добавлении или изменении сделки выполняется полная перезапись:

1. `DELETE` сделки из `read_deals` (каскадное удаление позиций из `read_positions` через FK).
2. `INSERT` сделки в `read_deals`.
3. `INSERT` всех текущих позиций в `read_positions`.

Тип события в `event_store`: `DealWithPositionsCreated`.



## Область синхронизации

Синхронизация выполняется строго в рамках одного листа (периода) Excel-книги.

- Каждый лист представляет собой один календарный месяц.
- Лист содержит все сделки за соответствующий месяц.
- Обработка выполняется последовательно: после завершения обработки одного листа система переходит к следующему.

### Важное исключение

Если лист (календарный месяц) удаляется из Excel-книги:

- данные, ранее загруженные в базу данных по данному листу, сохраняются;
- автоматическое удаление данных из базы не производится.

---

## Хранение истории изменений

Все изменения, вносимые в базу данных, фиксируются в таблице `event_store`.  
Это обеспечивает:

- возможность аудита изменений;
- восстановление полной цепочки событий;
- восстановление состояния системы при необходимости.

---

## Механизм идентификации данных

Синхронизация выполняется на основе `hash key`:

- отдельный hash key для сделки;
- отдельный hash key для позиции.

Hash key используется для определения факта добавления, изменения или удаления записи.

---

## Основные процессы системы

1. Парсинг данных из Excel-файла.
2. Детектирование изменений (формирование событий).
3. Запись событий в `event_store`.
4. Актуализация таблиц `read_deals` и `read_positions`.

---

## Ожидаемый результат

Таблицы `read_deals` и `read_positions` должны в любой момент времени отражать актуальное состояние соответствующего листа Excel-файла, при сохранении полной истории изменений в `event_store`.
