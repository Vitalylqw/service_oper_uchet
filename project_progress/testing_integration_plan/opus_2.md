# План интеграционного тестирования детектирования изменений

## 1. Структура Excel файла (формат данных)

### 1.1. Организация листов (Sheets)

Каждый лист книги Excel представляет **период** (месяц + год).

**Формат имени листа:** `"Месяц ГГГГ"` (например: `"Январь 2024"`, `"Февраль 2025"`)

**Правила:**

- Имя листа парсится через `Period.from_sheet_name()`
- Поддерживаемые месяцы: Январь, Февраль, Март, Апрель, Май, Июнь, Июль, Август, Сентябрь, Октябрь, Ноябрь, Декабрь
- Год: 4 цифры (2024, 2025, ...)
- Листы с некорректным форматом имени пропускаются парсером

### 1.2. Структура строк на листе

```
+---+------------------+--------------------+----------+-----+----------+--------+--------+--------------------+--------+--------+-----------+-------------+
|   | A (Клиент)       | B (Счёт)           | C (Отгр) | D   | E (Опл)  | F      | G      | H (Продавец)       | I      | J      | K         | L           |
+---+------------------+--------------------+----------+-----+----------+--------+--------+--------------------+--------+--------+-----------+-------------+
| 1 | Клиент           | Счет               | Отгружен | UPD | Оплачен  | Выручка| Маржа  | Продавец           | Закупка| Откат  | Поставщик | Дата забора |
+---+------------------+--------------------+----------+-----+----------+--------+--------+--------------------+--------+--------+-----------+-------------+
| 2 | ЛЕНТЕХСТРОЙ      | 5938 от 16.06.2025 | Нет      |     | Нет      | 145270 | 29713  | КРЕПЕЖ-ИНСТРУМЕНТ  | 30536  |        |           |             | <- MASTER (Deal)
| 3 |                  | Нож строительный   | 20       |     |          | 7120   |        |                    |        |        | этм       | 18          | <- DETAIL (Item 1)
| 4 |                  | Скребок MATRIX     | 44       | 108 | 210      | 9240   | 4458   |                    | 4781   |        | матрикс   | 19          | <- DETAIL (Item 2)
+---+------------------+--------------------+----------+-----+----------+--------+--------+--------------------+--------+--------+-----------+-------------+
```

### 1.3. Правила определения типа строки

**Master row (Deal)** - строка, где колонка A (Клиент) НЕ пустая:

| Колонка | Индекс | Поле Deal        | Обязательное |

|---------|--------|------------------|--------------|

| A       | 0      | client_name      | ДА           |

| B       | 1      | invoice_info     | ДА           |

| C       | 2      | is_shipped       | нет          |

| D       | 3      | upd_number       | нет          |

| E       | 4      | is_paid          | нет          |

| F       | 5      | total_revenue    | нет          |

| G       | 6      | total_margin     | нет          |

| H       | 7      | seller           | ДА           |

| I       | 8      | total_cost       | нет          |

| J       | 9      | kickback_amount  | нет          |

**Detail row (DealItem)** - строка, где колонка A пустая, но B (товар) заполнена:

| Колонка | Индекс | Поле DealItem    | Обязательное |

|---------|--------|------------------|--------------|

| B       | 1      | product_name     | ДА           |

| C       | 2      | quantity         | нет          |

| D       | 3      | purchase_price   | нет          |

| E       | 4      | sale_price       | нет          |

| F       | 5      | revenue          | нет          |

| G       | 6      | margin           | нет          |

| I       | 8      | cost             | нет          |

| J       | 9      | supplier_name    | нет          |

| K       | 10     | pickup_date      | нет          |

### 1.4. Уникальные ключи (для детектирования изменений)

**deal_key** = `invoice_number|invoice_date|seller|period` (normalized, lowercase)

- Пример: `"5938|16.06.2025|крепеж-инструмент ооо|май 2025"`

**item_key** = `hash(deal_key + position_number + product_name + supplier_name + quantity + prices + pickup_date)`

- position_number назначается автоматически (1, 2, 3, ...) для каждой сделки

## 2. Категории тестов с подробным описанием

### 2.1. ТЕСТЫ ЛИСТОВ (ПЕРИОДОВ)

#### SH-01: Добавление нового листа (нового периода)

**Описание:** В Excel добавляется новый лист с данными за новый период.

**Исходное состояние БД:**

- Период "Январь 2025": 2 сделки, 5 позиций

**Файл base.xlsx:**

```
Лист "Январь 2025":
  - Сделка 1: Клиент А, Счёт 001, 2 позиции
  - Сделка 2: Клиент Б, Счёт 002, 3 позиции
```

**Файл add_sheet.xlsx:**

```
Лист "Январь 2025":
  - Сделка 1: Клиент А, Счёт 001, 2 позиции
  - Сделка 2: Клиент Б, Счёт 002, 3 позиции
Лист "Февраль 2025":  <-- НОВЫЙ ЛИСТ
  - Сделка 3: Клиент В, Счёт 003, 2 позиции
```

**Ожидаемый результат:**

- `insertion_count` = 3 (1 новая сделка + 2 новые позиции)
- `update_count` = 0
- `deletion_count` = 0
- В БД появляется новый период "Февраль 2025" с 1 сделкой

**Проверки:**

```python
assert result.change_detection_result.insertion_count == 3
assert_period_exists_in_db("Февраль", "2025")
assert_deal_count_for_period("Февраль", "2025") == 1
assert_item_count_for_period("Февраль", "2025") == 2
```

---

#### SH-02: Удаление листа (удаление периода)

**Описание:** Лист с периодом удаляется из Excel.

**Файл base.xlsx:**

```
Лист "Январь 2025": 2 сделки
Лист "Февраль 2025": 1 сделка
```

**Файл remove_sheet.xlsx:**

```
Лист "Январь 2025": 2 сделки
(Лист "Февраль 2025" УДАЛЁН)
```

**Ожидаемый результат:**

- `insertion_count` = 0
- `update_count` = 0
- `deletion_count` = N (все сделки и позиции из "Февраль 2025")
- В БД сделки периода "Февраль 2025" помечены как удалённые (soft delete)

**Проверки:**

```python
assert result.change_detection_result.deletion_count > 0
assert_all_deals_deleted_for_period("Февраль", "2025")
```

---

#### SH-03: Переименование листа

**Описание:** Имя листа изменено (например, с "Январь 2025" на "January 2025").

**Примечание:** Так как период извлекается из имени листа, переименование на невалидное имя приведёт к пропуску листа. Переименование на другой валидный период (например, "Февраль 2025") эквивалентно удалению старого периода и добавлению нового.

### 2.2. ТЕСТЫ СДЕЛОК (DEAL)

#### D-01: Добавление новой сделки в существующий период

**Описание:** В существующий период добавляется новая сделка с позициями.

**Исходное состояние БД (из base.xlsx):**

```
Лист "Январь 2025":
  - Сделка 1: Клиент А, Счёт 001, Продавец X
```

**Файл add_deal.xlsx:**

```
Лист "Январь 2025":
  - Сделка 1: Клиент А, Счёт 001, Продавец X
  - Сделка 2: Клиент Б, Счёт 002, Продавец Y  <-- НОВАЯ СДЕЛКА
    - Позиция 1: Товар Б1
    - Позиция 2: Товар Б2
```

**Как внести изменение в Excel:**

1. На листе "Январь 2025" найти последнюю строку сделки
2. Добавить новую master row (с заполненным "Клиент")
3. Добавить detail rows под ней (с пустым "Клиент", но заполненным товаром)

**Ожидаемый результат:**

- `insertion_count` = 3 (1 сделка + 2 позиции)
- `update_count` = 0
- `deletion_count` = 0

**Проверки:**

```python
assert result.change_detection_result.insertion_count == 3
assert_deal_exists_in_db("002", "DD.MM.YYYY", "Продавец Y", "Январь 2025")
assert_item_count_for_deal(deal_id) == 2
```

#### D-02: Изменение client_name сделки

**Описание:** Изменение имени клиента в существующей сделке.

**Изменение в Excel:** Ячейка A (Клиент) master row: `"ЛЕНТЕХСТРОЙ"` → `"НОВЫЙ КЛИЕНТ"`

**Ожидаемый результат:**

- `update_count` >= 1
- В `field_changes` содержится `client_name`

**Проверки:**


#### D-03: Изменение invoice_info (номер и дата счёта)

**Описание:** Изменение информации о счёте.

**ВАЖНО:** Изменение invoice_number, invoice_date или seller меняет deal_key!

- Это означает: старая сделка будет помечена как УДАЛЁННАЯ, новая - как ВСТАВЛЕННАЯ

**Изменение в Excel:** Ячейка B: `"5938 от 16.06.2025"` → `"5939 от 17.06.2025"`

**Ожидаемый результат:**

- `insertion_count` >= 1 (новая сделка с новым deal_key)
- `deletion_count` >= 1 (старая сделка с прежним deal_key)

**Проверки:**

```python
# Старая сделка удалена
assert_deal_deleted(old_deal_key)
# Новая сделка создана
assert_deal_exists(new_deal_key)
```

### 2.3. ТЕСТЫ ПОЗИЦИЙ (DEAL ITEMS)

**Описание:** Добавление новой товарной позиции.

**Как внести изменение в Excel:**

1. Найти последнюю detail row сделки
2. Вставить новую строку под ней
3. Оставить колонку A пустой
4. Заполнить колонку B (товар) и остальные поля
```
Было:
| ЛЕНТЕХСТРОЙ | 5938 от 16.06.2025 | ...

Стало:
```

**Ожидаемый результат:**

#### I-08: Изменение порядка позиций (position_number)

**Описание:** Перемещение позиций внутри сделки.

**ВАЖНО:** position_number назначается автоматически при парсинге (1, 2, 3, ...).

Изменение порядка строк в Excel меняет position_number, что меняет item_key.

**Было:**

```
|             | Товар А    | ...  <- position_number = 1
|             | Товар Б    | ...  <- position_number = 2
```

**Стало:**

```
|             | Товар Б    | ...  <- position_number = 1 (было 2)
|             | Товар А    | ...  <- position_number = 2 (было 1)
```

**Ожидаемый результат:**

- `insertion_count` = 2 (новые item_key)
- `deletion_count` = 2 (старые item_key)

## 4. Шаблон теста

```python
@pytest.mark.integration
async def test_D01_add_deal(clean_db, sync_orchestrator, excel_generator):
    """D-01: Добавление новой сделки в существующий период."""
    # 1. ARRANGE: Загрузить базовые данные
    base_file = excel_generator.create_base_scenario()
    await sync_and_commit(base_file, sync_orchestrator)
    
    # Проверить начальное состояние
    assert_deal_count_for_period("Январь", "2025") == 1
    
    # 2. ACT: Загрузить файл с изменениями
    modified_file = excel_generator.create_scenario_D01()
    result = await sync_and_commit(modified_file, sync_orchestrator)
    
    # 3. ASSERT: Проверить детектирование
    assert result.change_detection_result.insertion_count == 3  # 1 deal + 2 items
    assert result.change_detection_result.update_count == 0
    assert result.change_detection_result.deletion_count == 0
    
    # Проверить состояние БД
    assert_deal_count_for_period("Январь", "2025") == 2
    assert_deal_exists("002", "01.01.2025", "Продавец Y", "Январь 2025")
```
