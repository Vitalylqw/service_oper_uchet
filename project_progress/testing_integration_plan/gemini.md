# План: Комплексный QA Suite для синхронизации данных

## Цель

Разработать надежный, изолированный стенд для интеграционного тестирования логики синхронизации (`qa_suite`). Стенд должен проверять корректность переноса данных из Excel в БД при любых изменениях: добавлении строк, обновлении полей, удалении позиций и добавлении новых листов (периодов).

## Стратегия

Мы создаем отдельную директорию `qa_suite`, которая будет работать как внешний потребитель кода из `src`. Основной упор делается на **динамическую генерацию Excel-файлов** через Python, чтобы моделировать любые пользовательские сценарии без хранения бинарных файлов.

## Архитектура

### Структура директорий

```
qa_suite/
├── README.md                 # Инструкция по запуску и описанием тестов
├── requirements.txt          # Зависимости: pytest, pytest-asyncio, pandas, openpyxl, sqlalchemy, asyncpg
├── conftest.py               # Фикстуры: подключение к БД, очистка таблиц, event loop
├── factories/
│   ├── __init__.py
│   └── excel_builder.py      # Класс-строитель для генерации .xlsx файлов "на лету"
└── tests/
    └── test_integration_sync.py # Сценарии тестирования
```

### Компоненты

#### 1. Excel Builder (`factories/excel_builder.py`)

Мощный инструмент для создания Excel файлов, повторяющий структуру реальных отчетов.

-   **Возможности**:
    -   Создание книги с N листами.
    -   Именование листов по формату "Месяц Год" (важно для парсера).
    -   Добавление "мастер-записей" (Сделки) и "детальных записей" (Позиции).
    -   Поддержка формул (Excel Parser их читает) или статических значений.
    -   Гибкая настройка колонок (чтобы проверить устойчивость к перестановкам, если парсер это допускает, или фиксированную структуру).

#### 2. Тестовые Сценарии (`test_integration_sync.py`)

Каждый тест должен проходить по схеме: **Arrange (Подготовка) -> Act (Действие) -> Assert (Проверка)**.

**Сценарий 1: Базовая загрузка (Cold Start)**

-   *Действие*: Генерируем файл с 1 листом "Январь 2024", 2 сделки, 5 позиций. Запускаем синхронизацию.
-   *Проверка*: В БД ровно 2 сделки и 5 позиций. Поля (выручка, маржа) совпадают.

**Сценарий 2: Идемпотентность (Повторная загрузка)**

-   *Действие*: Берем файл из Сценария 1 и загружаем его же второй раз.
-   *Проверка*: В БД нет изменений. `updated_at` не изменился. Логи показывают 0 изменений.

**Сценарий 3: Изменение данных (Update)**

-   *Действие*: В файле меняем цену у одной позиции.
-   *Проверка*: В БД у этой позиции обновилась цена и пересчитались итоги (выручка, маржа). `updated_at` обновился. Остальные записи не тронуты.

**Сценарий 4: Добавление позиций (Insert Item)**

-   *Действие*: В существующую сделку в Excel добавляем новую строку (позицию).
-   *Проверка*: В БД появилась новая позиция. Общее количество позиций в сделке увеличилось.

**Сценарий 5: Удаление позиций (Delete Item)**

-   *Действие*: Удаляем строку из Excel.
-   *Проверка*: В БД соответствующая позиция удалена (Hard Delete или Soft Delete в зависимости от реализации).

**Сценарий 6: Новые периоды (New Sheet)**

-   *Действие*: К файлу с "Январь 2024" добавляем лист "Февраль 2024" с новыми сделками.
-   *Проверка*: Данные за Январь не затронуты. Данные за Февраль появились в полном объеме.

**Сценарий 7: Сложные формулы (Formula Check)**

-   *Действие*: Ячейка "Выручка" содержит формулу `=Цена*Кол-во`.
-   *Проверка*: Парсер корректно вычислил значение и сохранил число в БД.

## План реализации

1.  **Подготовка окружения**: Создать папку `qa_suite` и `requirements.txt`.
2.  **Реализация ExcelBuilder**: Написать класс на базе `pandas`/`openpyxl`, который умеет создавать валидный для парсера файл (с правильными заголовками: "Клиент", "Выручка" и т.д.).
3.  **Настройка БД**: В `conftest.py` настроить создание временной БД или подключение к существующей тестовой БД.
4.  **Написание тестов**: Реализовать описанные выше сценарии шаг за шагом.
5.  **Документация**: Описать в README, как запускать тесты и как читать отчеты об ошибках.

## Детали реализации файла (Excel Structure)

Согласно коду `parser.py`, файл должен иметь:

-   Заголовок, где есть колонка "Клиент".
-   Имя листа, содержащее месяц и год (для `Period`).
-   Колонки по порядку (или по именам, если парсер умный, но код опирается на индексы `safe_get(idx)`):

0: Client Name

1: Invoice Info/Product Name

2: Is Shipped / Quantity

3: UPD / Purchase Price

4: Is Paid / Sale Price

5: Revenue

6: Margin

7: Seller

... и т.д.

-   Структура "Master-Detail" определяется наличием `client_name` (Master) или отсутствием (Detail, берется из контекста).

Мы учтем эту структуру в `ExcelBuilder`.
