## 📋 ОПИСАНИЕ ИЗМЕНЕНИЯ

Добавлен период (`period`) в конкатенацию `deal_key` для обеспечения уникальности сделок по периодам.

### До изменения:
```
deal_key = "client_name|invoice_number|invoice_date|seller"
```

### После изменения:
```
deal_key = "client_name|invoice_number|invoice_date|seller|period_full_name"
```

---

## 🎯 ЦЕЛЬ ИЗМЕНЕНИЯ

**Проблема:** Сделки с одинаковыми данными, но разными периодами, считались дубликатами.

**Решение:** Добавление `period` в `deal_key` обеспечивает уникальность сделок по периодам.

**Примеры:**
- **До:** `ООО Клиент|123|01.01.2025|Иванов` (одинаковый ключ для разных месяцев)
- **После:** 
  - `ООО Клиент|123|01.01.2025|Иванов|Январь 2025`
  - `ООО Клиент|123|01.01.2025|Иванов|Февраль 2025`

---

## 🔧 РЕАЛИЗОВАННЫЕ ИЗМЕНЕНИЯ

### 1. Domain модель (`src/domain/models/deal.py`)
```python
@computed_field
@property
def deal_key(self) -> str:
    """Уникальный ключ сделки для обнаружения изменений."""
    return f"{self.client_name}|{self.invoice_number or ''}|{self.invoice_date or ''}|{self.seller or ''}|{str(self.period)}"
```

### 2. Согласованность с hash_key
`hash_key` уже включал `period`, поэтому дополнительных изменений не потребовалось.

## 📈 ПРИМЕРЫ ИСПОЛЬЗОВАНИЯ

### Создание сделки с новым deal_key:
```python
from domain.models.deal import Deal
from domain.value_objects.common import Period

period = Period(month="Январь", year="2025", full_name="Январь 2025")
deal = Deal(
    client_name="ООО Пример",
    invoice_info="Счет № 123 от 15.01.2025",
    period=period
)
deal.invoice_number = "123"
deal.invoice_date = "15.01.2025"
deal.seller = "Иванов И.И."

print(deal.deal_key)
# Результат: "ООО Пример|123|15.01.2025|Иванов И.И.|Январь 2025"
```

### Уникальность по периодам:
```python
# Две одинаковые сделки, но разные периоды
deal_jan = Deal(..., period=Period(..., full_name="Январь 2025"))
deal_feb = Deal(..., period=Period(..., full_name="Февраль 2025"))

print(deal_jan.deal_key != deal_feb.deal_key)  # True - разные ключи
```
