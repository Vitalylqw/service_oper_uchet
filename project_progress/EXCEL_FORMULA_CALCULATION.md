# Реализация вычисления формул Excel

**Дата:** 12 октября 2025  
**Статус:** ✅ Обновлено

---

## Описание задачи

Гарантировать, что Excel парсер использует кэшированные значения формул, пересчитанные LibreOffice в headless-режиме перед чтением.

## Проблема

Мастер-строки в Excel содержат формулы для итоговых значений:
- `total_revenue`: `=SUM(F5:F16)` 
- `total_margin`: `=SUM(G5:G16)`
- `total_cost`: `=SUM(I5:I16)`

При парсинге через `openpyxl` с параметром `data_only=True` возвращались `None` (пустой кэш формул).

Попытка пересохранения через openpyxl не помогла, так как библиотека не вычисляет формулы, а только копирует их.

## Решение

### 1. Предвычисление LibreOffice (headless)

```bash
libreoffice --headless --norestore --convert-to xlsx --outdir <outdir> <file.xlsx>
```

- Пересчитывает формулы и сохраняет новый `.xlsx` с актуальными значениями.
- Используем копию, не затрагивая оригинал.

### 2. Кеширование результата

- Копия сохраняется в каталоге `excel_precalc_cache/` рядом с файлом или в `EXCEL_PARSER_PRECALC_OUTDIR`.
- Имя содержит md5 оригинала (`<stem>-<md5>.xlsx`); повторный расчёт выполняется только при изменении исходника.
- Срок жизни управляется `EXCEL_PARSER_PRECALC_TTL_DAYS`.

### 3. Интеграция в парсер

- Перед чтением `load_workbook` вызывается `refresh_excel_cache_if_enabled()`.
- В режиме `cache_only` получаем данные через `data_only=True` из пересчитанной копии.
- В `no_cache` и `hybrid` сохраняются заданные правила по формульным ячейкам.

### 4. Ошибки и fallback

- Отсутствие LibreOffice / таймаут / ошибка конвертации → предупреждение и возврат к исходному файлу, поведение не ломается.
- Старые кэши автоматически очищаются.

## Ограничения

Ограничения связаны с LibreOffice:
- Требует установленный пакет `libreoffice` (`apt install libreoffice-calc`).
- Первое выполнение может занимать дольше из-за инициализации профиля.
- Поддерживаются форматы, совместимые с LibreOffice Calc.

## Режимы работы парсера Excel (EXCEL_PARSER_CACHE_MODE)

Требуемая спецификация режимов для ячеек с формулами. Для ячеек БЕЗ формул — всегда
используются фактические данные как есть.

- no_cache: никакого кэша и НИКАКИХ вычислений формул. Возвращаем то, что в файле —
  для формульных ячеек это будут строки формул либо пустые значения (None), система
  сама обработает. Итоговые `total_*` НЕ рассчитываются.
- cache_only: никаких вычислений; использовать только кэшированные значения для
  формульных ячеек (`data_only=True`). Если кэш отсутствует — возвращать None.
- hybrid: если в формульной ячейке есть кэш — берём его; если кэша нет — вычисляем
  значение формулы (xlcalculator + ручные методы для SUM), иначе None.

Замечание: семантика распространяется на все формульные ячейки, включая `total_*`.

## Примечание по реализации (текущее состояние vs требование)

- В текущей реализации в режиме `no_cache` инициализируется вычислитель формул и
  итоговые значения `total_*` могут заполняться вычисленными числами. Это расходится
  с требованием «никаких вычислений». Для приведения к спецификации требуется:
  - не инициализировать `evaluator` в `no_cache`;
  - для формульных ячеек всегда возвращать исходные значения (строки формул) либо None.

Обновление кода будет выполнено после подтверждения, тесты будут дополнены кейсами
для всех трёх режимов.
