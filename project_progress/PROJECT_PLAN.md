# План проекта

## Цель

Поддерживать надежный и проверяемый контур синхронизации:

- Excel -> parsing;
- parsing -> change detection;
- change detection -> event_store;
- event_store -> read models;
- read models -> snapshot/dashboard-проверки.

## Активный scope

1. Удерживать в актуальном состоянии Excel-based sync flow без возврата скрытой сложности
   `is_active/version`.
2. Сохранять согласованность между кодом, миграциями, тестами и документацией.
3. Поддерживать технические инструменты проверки:
   `testing/scripts/`, `dashboard/`, `read_stats`, `db_snapshots`.

## Текущий этап

### Этап A. Актуализация документации

Что входит:

- привести активную документацию к текущему scope проекта;
- убрать противоречия с кодом и реальной структурой репозитория;
- перенести исторические техотчеты в архив без потери информации;
- зафиксировать канонические документы для входа в проект.

Что не входит:

- изменение бизнес-логики синхронизации;
- рефакторинг кода без отдельной задачи;
- переработка конфигурационной модели `.env` / `config.env`.

## Следующие рабочие направления

### Направление 1. Проверка качества синхронизации

- разобраться с кейсами из `project_progress/STATUS.md` и archived TODO;
- проверить корректность `has_totals_error` при `NULL` declared totals;
- проверить, почему в некоторых сценариях `event_store` получает больше событий, чем ожидается.

### Направление 2. Аудит и наблюдаемость

- завершить удаление `read_audit` как неиспользуемого legacy-слоя;
- сохранить `event_store` единственным источником истории изменений;
- продолжать использовать snapshot/dashboard как основной инструмент контроля целостности.

### Направление 3. Конфигурация окружения

- зафиксировать каноническую схему env-конфигурации;
- при отдельном согласовании свести использование `config.env` и `.env` к понятному правилу.

## Ограничения и риски

- Исторические документы нельзя удалять без проверки их ценности для архитектурной памяти.
- Документация не должна утверждать то, что не подтверждено кодом или фактической проверкой.
- Любые будущие изменения sync flow нужно сначала сверять с `.cursor/rules/project_goals.md`.
