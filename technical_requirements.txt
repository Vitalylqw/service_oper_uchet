# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
# Система синхронизации данных Excel → PostgreSQL (jsonb) с версионностью

## 1. ОБЩАЯ ИНФОРМАЦИЯ

### 1.1 Назначение системы
**Система синхронизации и версионирования данных** предназначена для автоматического переноса данных из Excel файлов,
 с которыми работают пользователи, в централизованную базу данных PostgreSQL (версия ≥ 16) для анализа и долгосрочного хранения
 с полной историей изменений.

### 1.2 Бизнес-задача
- **Пользователи ежедневно работают** с Excel файлом, добавляя и изменяя данные
- **Система автоматически** получает файл с другого компьютера 1 раз в день
- **Обнаруживает изменения** и синхронизирует их с базой данных
- **Сохраняет полную историю** всех изменений для аудита и анализа
- **Обеспечивает целостность** данных между Excel и БД

### 1.3 Ключевые особенности
- **ETL процесс** с поддержкой инкрементальных обновлений
- **Версионность данных** - хранение истории изменений
- **Автоматическая синхронизация** по расписанию
- **Детальный аудит** всех операций
- **Мониторинг** состояния синхронизации

### 2.2 Архитектурный подход
**Domain Driven Design (DDD)** + **Event Sourcing** + **CQRS**

**Структура приложения**:
- **domain/** - Предметная область (сущности, объекты-значения, репозитории)
- **application/** - Сценарии использования (синхронизация, обнаружение изменений, аудит)
- **infrastructure/** - Инфраструктура (БД, Excel, файловая система, планировщик)
- **presentation/** - Интерфейсы (REST API, CLI, Web)

### 2.3 Технологический стек
- **Python 3.9+** - основной язык разработки
- **FastAPI** - веб-фреймворк для API
- **SQLAlchemy 2.0** - ORM для работы с БД
- **Pandas** - обработка данных Excel
- **Pydantic** - валидация данных
- **Alembic** - миграции БД
- **Loguru** - структурированное логирование

### 2.4 Event Sourcing & CQRS Details
**Формат события**: JSONB с полями `id`, `aggregate_id`, `event_type`, `event_data`, `metadata`, `created_at`.

**Хранение**: таблица `event_store` партиционируется по месяцу, индекс GIN по (`event_data`).

**Upcaster Pattern**: при чтении события версия проверяется и, при необходимости, преобразуется к актуальной схеме.

**Проекции (read-model)**: асинхронный worker (Celery) создаёт/обновляет представления в схеме `read_*`.

## 4. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

### 4.1 Получение файлов

#### 4.1.1 Автоматическое получение
- **Источник**: Excel файл на удаленном компьютере
- **Частота**: 1 раз в день в настраиваемое время
- **Протокол**: SMB/CIFS, FTP, SFTP или HTTP API
- **Проверка целостности**: контрольная сумма файла
- **Резервирование**: сохранение копии с timestamp

#### 4.1.2 Мониторинг файлов
- **Обнаружение изменений**: сравнение даты модификации и размера файла
- **Валидация**: проверка формата Excel и целостности структуры
- **Уведомления**: email алерты при ошибках получения
- **Retry логика**: настраиваемое количество повторных попыток

### 4.2 Обнаружение изменений

#### 4.2.1 Алгоритм сравнения
**Принцип работы**:
1. Сравнение записей по уникальным ключам
2. Хэширование записей для быстрого обнаружения изменений
3. Детальное сравнение измененных записей по полям
4. Классификация изменений: INSERT (новые), UPDATE (измененные), DELETE (удаленные)

**Типы синхронизации**:
- **Полная синхронизация**: обработка всех данных в файле независимо от периода
- **Инкрементальная синхронизация**: обработка только данных за настраиваемый период (по умолчанию 3 месяца)
- **Автоматическое определение**: система выбирает тип синхронизации по расписанию

#### 4.2.2 Уникальные ключи
- **Для сделок**: комбинация `client_name + invoice_number + invoice_date + saller`
- **Для позиций товаров**: комбинация `deal_key + product_name + supplier_name`
- **Хэширование**: MD5 от JSON представления нормализованной записи
- **Кэширование**: хранение хэшей в БД для быстрого сравнения

### 4.3 Требования к хранению данных

#### 4.3.1 Основные данные
Система должна хранить следующие типы данных:

**Сделки с клиентами**:
- Информация о клиенте и продавце
- Реквизиты счетов и документов (номер, дата, УПД)
- Статусы (отгружен, оплачен)
- Финансовые показатели (выручка, маржа, стоимость)
- Временной период (месяц, год)

**Позиции товаров**:
- Наименование товара и поставщик
- Количественные показатели (количество, цены)
- Финансовые показатели по позиции
- Дата забора товара у поставщика

#### 4.3.2 Требования к версионности
Система должна обеспечивать:

**Полную историю изменений**:
- Сохранение каждой версии записи при изменении
- Фиксация типа изменения (добавление/изменение/удаление)
- Привязка к конкретной сессии синхронизации
- Временные метки всех операций

**Аудит операций**:
- Журнал всех сессий синхронизации с результатами
- Детальное логирование каждого изменения
- Статистика обработки данных
- Информация об ошибках и их причинах

#### 4.3.3 Требования к производительности БД
- **Быстрый поиск**: индексы по ключевым полям
- **Обнаружение изменений**: хэши записей для сравнения
- **Масштабируемость**: поддержка роста объема данных
- **Целостность**: транзакционность операций

### 4.4 Процесс синхронизации

#### 4.4.1 Валидация и контроль данных

**Интеграция с 1С через HTTP-микросервис**:
- **Базовый URL**: вынемен в настроки, по умолчанию http://1c-bridge.local/api/v1/`
- **Протокол**: REST / JSON
- **Аутентификация**: сервисный JWT-токен
- **Лимит**: ≤ 60 запросов в минуту
- **Эндпоинт `/deals`**: выгрузка сделок за период

**Контроль структуры Excel файла**:
- **Проверка фиксированной шапки**: валидация заголовков и их позиций
- **Контроль структуры товаров**: проверка корректности данных по позициям
- **Финансовая сверка**: сумма строк должна равняться итоговым показателям в шапке
- **Обнаружение некорректной структуры в файле Excel**:  смещений данных в ячейках, удаленных строк или столбцов
, появление разрывов в таблице, и т.д.
- **Пропуски и ошибки**: идентификация отсутствующих обязательных данных
- **Игнорирование некорректных сделок**: исключение записей с нарушениями логики
- **Детальные предупреждения**: сообщения о найденных проблемах с указанием строк/столбцов

#### 4.4.2 Основные этапы
1. **Создание сессии синхронизации** с уникальным идентификатором
2. **Получение файла** с проверкой изменений
3. **Парсинг Excel данных** с валидацией структуры
4. **Проверка данных с 1С** через API интеграцию
5. **Получение текущего состояния** из базы данных
6. **Обнаружение изменений** по алгоритму сравнения
7. **Применение изменений** в транзакции с сохранением истории
8. **Завершение сессии** с записью статистики и отчетов

#### 4.4.3 Обработка изменений
- **Новые записи**: добавление в основные таблицы + запись в историю
- **Измененные записи**: обновление основных таблиц + сохранение старой версии в историю
- **Удаленные записи**: мягкое удаление (флаг is_active=false) + запись в историю
- **Логирование событий**: детальная запись каждого изменения

### 4.5 Планирование и автоматизация

#### 4.5.1 Планировщик задач
- **Расписание**: ежедневно в настраиваемое время (по умолчанию 03:00)
- **Конфигурация**: через файл настроек 
- **Мониторинг выполнения**: логирование старта, завершения и ошибок, режим отладки с подробным логированием
- **Уведомления**: email отчеты о результатах синхронизации
- **Исполняющий механизм**: APScheduler внутри сервиса; Windows Task Scheduler — резервный watchdog

#### 4.5.2 Настройки регулярности синхронизации
- **Полная синхронизация**: настраиваемая периодичность полной выгрузки файла (по умолчанию еженедельно)
- **Инкрементальная синхронизация**: настраиваемое количество последних месяцев для ежедневного обновления (по умолчанию 3 месяца)
- **Гибкие настройки**: возможность изменения периодичности в зависимости от потребностей бизнеса
- **Автоматическое переключение**: система автоматически определяет тип синхронизации по расписанию

#### 4.5.3 Обработка ошибок
- **Retry механизм**: настраиваемое количество повторных попыток
- **Откат транзакций**: полный откат при критических ошибках
- **Частичная обработка**: продолжение при некритических ошибках
- **Детальное логирование**: сохранение всех ошибок для анализа

### 4.6 API для доступа к данным

#### 4.6.1 Основные эндпоинты
**Данные**:
- Получение списка сделок с фильтрацией и пагинацией
- Детальная информация о сделке с позициями
- Поиск данных по различным критериям

**История и аудит**:
- История изменений конкретной сделки или позиции
- Список сессий синхронизации с статистикой
- Журнал всех изменений с фильтрацией

**Аналитика**:
- Сводная статистика по периодам
- Тренды изменений данных
- Метрики производительности синхронизации

#### 4.6.2 Форматы данных
- **Входные данные**: JSON, query parameters для фильтрации
- **Выходные данные**: JSON с метаданными пагинации
- **Коды ответов**: стандартные HTTP статусы

## 5. НЕФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

### 5.1 Производительность
- **Время синхронизации**: обработка до 1000 сделок за 5 минут
- **Полная синхронизация**: обработка всех данных файла за время менее 30 минут
- **Инкрементальная синхронизация**: обработка данных за 3 месяца за время менее 5 минут
- **Обнаружение изменений**: анализ различий за время менее 60 секунд
- **API отклик**: время ответа менее 2 секунд для стандартных запросов
- **Размер файлов**: поддержка Excel файлов до 100 MB

### 5.2 Надежность
- **Доступность**: 99.9% с учетом планового технического обслуживания
- **Транзакционность**: полная откатываемость всех изменений при ошибках
- **Резервное копирование**: ежедневные backup БД и файлов
- **Восстановление**: процедуры восстановления в течение 1 часа

### 5.3 Безопасность
- **Аутентификация**: OAuth 2.1 (PKCE) + JWT, срок жизни access-token 15 мин, refresh-token 7 дней
- **Авторизация**: RBAC (`admin`, `analyst`, `viewer`)
- **Шифрование**: TLS 1.2+ для всех HTTP-соединений, шифрование backup AES-256
- **Хранение секретов**: Windows Credential Manager / HashiCorp Vault

### 5.4 Мониторинг и логирование
- **Структурированные логи**: JSON формат с контекстной информацией
- **Уровни логирования**: DEBUG, INFO, WARNING, ERROR, CRITICAL
- **Ротация логов**: по размеру и времени
- **Метрики**: производительность, ошибки, объемы данных

### 5.5 SLA / SLO
| Метрика | SLO | Способ измерения |
|---------|-----|------------------|
| Доступность API | 99.9 % | UptimeRobot / Grafana |
